# ADR-0006：入口不对称与不设统一门面

- 状态：`accepted`
- 日期：2026-09-19

## 背景

GUI 需要交互式状态和浮层，CLI 需要管道与退出码，MCP 需要少量结构化工具，HTTP 还要处理远程安全。强制三入口使用同一请求、响应和事件流，会把最弱入口的限制传给所有入口。

## 决策

每个能力按需选择暴露入口。共享业务规则、领域模型、存储和算法；入口的 DTO、错误呈现、通知和生命周期可以不同。不存在“每功能 × 三入口”的全矩阵，也不存在统一 `Capability`、`Engine.Submit` 或全局 `Event` 门面。

## 后果

适配代码可能有重复，但重复局限在边界层，换来的是真实的入口体验和更小的安全暴露面。入口矩阵和每项能力的暴露理由必须写入文档。

## 被否决方案

- 三入口完全对称：忽略入口真实差异。
- 适配代码绝不重复：会制造过度抽象和隐式耦合。
