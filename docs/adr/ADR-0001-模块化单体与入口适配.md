# ADR-0001：模块化单体与入口适配

- 状态：`accepted`
- 日期：2026-09-19

## 背景

Wailf 需要同时支持本地 Wails GUI、脚本化 CLI、MCP 和未来 server 模式。能力域数量多，C2/WebShell 还需要持续会话；从一开始拆成多个服务会给桌面部署、数据一致性和调试带来不必要的成本。

## 决策

采用 Go 模块化单体。领域按垂直切片组织，平台层提供存储、Job、Artifact、审计和秘密引用。GUI、CLI、MCP 和 HTTP 分别是入口适配器，由同一个 composition root 按启动模式组装。

共享领域模型、存储端口和算法；不共享入口协议，也不要求所有能力实现同一个公共接口。

## 后果

- 本地部署简单，Job、Session 和 Artifact 可以在同一进程/数据库内关联。
- 领域包必须保持对 Wails、Cobra、MCP SDK 和 HTTP 的隔离。
- 未来拆服务时可以沿领域和平台端口拆分，但不能把当前入口适配器直接当作服务 API。
- 单体进程的资源和权限边界需要通过 Connector、Job 上限和审计补足。

## 被否决方案

- 首期客户端/服务端分离：运维和离线成本过高。
- GUI 独占核心、CLI/MCP 后置：会导致自动化契约欠缺。
