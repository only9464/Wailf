# ADR-0008：平台主题与用户主题分层

- 状态：`accepted`
- 关联补充：[ADR-0011：Windows 原生 Acrylic 材质](ADR-0011-windows-acrylic-material.md)
- 日期：2026-09-19
- 主题契约：`theme.v1`
- 运行时基线：Wails 3 `v3.0.0-beta.20`（`@wailsio/runtime` 与生成 bindings 同一兼容线）

## 背景

Wailf 的 GUI 运行在 Wails WebView 中，同时要支持 Windows、macOS、Linux、Android、iOS 和普通浏览器开发环境。平台之间存在系统字体、窗口安全区、标题栏、输入法、滚动条和资源路径等差异；用户还需要保存自己的颜色和密度偏好。

现有前端基线已经规定主题属于 GUI 偏好，存储通过封装后的 `localStorage` 访问，组件不得直接读取浏览器 API。当前脚手架的 `style.css` 仍包含大量 hex、rgba、gradient 和背景图片硬编码。如果让每个组件自行判断平台或接受任意 CSS，会导致：

- 平台探测、视觉 token 和窗口 hooks 互相耦合；
- 损坏的 localStorage 或资源加载失败阻塞 GUI 启动；
- 用户主题无法版本迁移，且任意 CSS/URL 带来注入和供应链风险；
- CLI、MCP、未来 HTTP server 被迫依赖 GUI 状态；
- Wails runtime API 在 `latest`/跨 beta 变化时产生不可诊断的启动差异。

需要一个能在浏览器/SSR 中安全退化、在 Wails GUI 中利用原生环境信息、并且可测试和长期迁移的主题边界。

## 决策

### 1. 主题是 GUI-only 能力

主题初始化、DOM 属性、CSS custom properties、平台资源和 GUI `localStorage` 只属于 Wails GUI。`wailf cli`、`wailf mcp` 和未来 `wailf server`/HTTP adapter：

- 不读取 `wailf.ui.theme` 或任何 GUI localStorage；
- 不调用 `System.Environment` 来决定输出；
- 不把主题字段加入入口协议、工具 schema、业务 DTO 或审计数据；
- 不加载 GUI 平台资源。

类型和纯校验函数可以复用，但带有 DOM、runtime、storage 或资源副作用的模块不得从这些入口导入。

### 2. 使用固定三层 cascade

解析顺序固定为：

```text
base (platform 或 default) -> platform token layer -> user ThemeDefinition
```

- `base="platform"` 是默认路径：使用中性 default token，再叠加已归一化 `PlatformId` 的平台 token。
- `base="default"` 只使用中性 token，用于兼容/预览/未知环境。
- 两种 base 都保留平台 hooks；`base` 只控制 token，不关闭安全区、标题栏、输入法和 reduced-motion 等 hooks。
- 已知平台的 CSS link 始终加载；平台文件把视觉 token 放在 `data-theme-base="platform"` 条件下，把 safe-area、标题栏和拖拽等 chrome hook 放在 `data-platform` 条件下，因此 `base="default"` 仍能获得平台 hook。
- 根元素的 `data-theme-base` 只取 `platform`/`default`，平台 token 不能以 `data-platform` 作为 CSS 选择器来源。
- 根元素始终设置 `data-platform=<PlatformId>`；该属性只供 hooks 使用。

用户层只能覆盖 `TokenRegistry` 声明的语义 token，不能提交 CSS、脚本、选择器、资源 URL 或持久化 hooks。关键平台 hooks 始终由已校验的 `PlatformDescriptor` 恢复。

### 3. 固定 `PlatformId` 与 `PlatformDescriptor`

`PlatformId` 封闭为：`windows`、`darwin`、`linux`、`android`、`ios`、`web`、`unknown`。运行时的 `EnvironmentInfo` 必须先归一化为静态 `PlatformDescriptor`，描述符保留脱敏的 `rawOS`，并包含 `runtimeMode`（`desktop|mobile|server|browser|unknown`）和 `formFactor`（`desktop|mobile|unknown`），只引用静态 token set、hooks 和资源 ID allowlist，不携带任意 URL。

原生 GUI 优先使用 `System.Environment()` 的 `OS`/`OSInfo`；若 `PlatformInfo.mode=server`，归一化为渲染端 `web`，不能把服务器主机 OS 当作 GUI 平台；无 DOM 的 SSR 不调用它；普通浏览器最多归一化为 `web`，不把 User-Agent 当作安全事实。

首期不新增业务 Go `RuntimeInfoService` 或自定义平台 endpoint；`PlatformProvider` 只封装 Wails runtime，避免把 GUI 环境信息混入领域模型和其他入口。

### 4. 启动时异步探测，有限超时且可回退

`index.html` 先同步加载 `frontend/public/style.css` 作为完整 default 基底；主题 bootstrap 再写入中性根状态 `data-theme-base="default"`、`data-platform="unknown"`，注册 `wails:runtime-config-ready` 补偿监听，并通过锁定 runtime 异步调用 `System.Environment()`。只允许一个 in-flight probe，事件只唤醒一次未就绪的 probe；调用有约 `500ms` 上限，Vue 应立即挂载，不能无限等待路由或业务请求。

- 成功且 OS 已知：使用对应 descriptor 和三层 cascade。
- 成功但 OS 未知：使用 `unknown` + default token。
- 异常、超时、404、描述符/资源形状非法：不阻塞、不抛出启动错误，回退到可渲染 default/platform，并保留 hooks。
- 晚到的合法结果只有在用户选择的 preference revision 未变化时才可以更新 token 和属性；不得覆盖刚选择的主题、重载路由、清空状态或改变业务语义。

### 5. 主题持久化采用多键契约

活动指针固定为：

```text
wailf.ui.theme = {
  "version": 1,
  "mode": "platform" | "custom",
  "customId": string | null
}
```

用户定义固定为 `wailf.ui.theme.custom.<id> = ThemeDefinition`，其中 `ThemeDefinition` 的 `version` 为 `1`、`name` 为安全纯文本、`base` 为 `platform|default`，只有 token 受 registry 校验。`id`、`customId` 和 key 后缀必须是同一规范化小写 ASCII ID；v1 导入遇到重复/冲突 ID 时拒绝整个批次，不覆盖已有定义。写入采用“先定义、后指针”；损坏、缺失、旧字符串、禁用 storage 或配额异常均回退，不污染业务存储。

导入/导出另使用 `ThemeBundle`（`kind="wailf-theme-bundle"`、`version=1`、`themes[]`）。bundle 只携带用户定义，不携带活动指针、平台 descriptor、hooks 或业务数据；导入必须全量校验并原子提交，冲突或任一条定义非法时不写入任何定义，也不自动切换当前主题。由于 `localStorage` 没有跨 key 事务，采用 staging key + commit marker，并在启动时恢复或清理未完成批次。成功导入后由 GUI 显式调用主题选择流程。

### 6. 平台资源使用构建时 `BASE_URL` 和 allowlist

平台资源只能来自同源、构建产物或 Wails 嵌入 asset server。`THEME_BASE_URL = import.meta.env.BASE_URL + "themes/platform/"` 是构建时派生值，不得由 localStorage、查询参数或用户定义覆盖。首期平台文件为 `frontend/public/themes/platform/{windows,darwin,linux,android,ios}.css`，`web`/`unknown` 不加载平台覆盖文件。资源通过 `PlatformResourceId -> relativePath` 静态映射解析，拒绝路径遍历、外源协议、外源重定向、未经声明的 MIME/大小和外部 `@import`。

现有根目录背景图片继续由基础 `style.css` 管理，不是 v1 用户主题资产；平台背景若未来加入，必须另建静态 manifest 和资源根。

资源 `404`、超时或校验失败只跳过该资源，继续使用已验证 token；资源错误不是 GUI 启动错误。

### 7. 运行时版本锁定

Wails CLI、Go runtime、`@wailsio/runtime`、生成 bindings 和文档基线锁定 Wails 3 `v3.0.0-beta.20` 兼容线。依赖文件不得使用 `latest` 或允许跨 beta 自动升级；任何 runtime 升级必须同步重新生成 bindings、运行主题启动/回退测试并提交新的 ADR 或更新本 ADR 的 supersession 记录。主题实现不得根据多个 beta API 猜测行为。

## 后果

正面后果：

- 平台视觉差异、平台 hooks 和用户偏好有清晰的所有权与覆盖顺序；
- GUI 在无 runtime、损坏 storage、超时或缺资源时仍可启动；
- token registry 和多键 schema 为未来编辑器、导入/导出和版本迁移提供稳定边界；
- CLI/MCP/HTTP 保持入口不对称，不会因 GUI 偏好或 WebView 能力改变业务结果；
- allowlist、同源 `BASE_URL` 和 fail-closed 校验缩小 CSS/资源注入面；
- runtime pin 使 `System.Environment`、bindings 和启动行为可复现。

代价与限制：

- 需要维护 registry、平台 descriptor、资源 manifest、迁移器和较完整的测试矩阵；
- 新增平台或 token 必须更新类型、allowlist、默认值和回退测试；
- 用户不能直接粘贴任意 CSS，也不能把远程资源作为主题资产；
- `System.Environment` 是异步调用，启动初始帧可能短暂使用 default token，晚到结果需要安全地更新 DOM；
- 当前脚手架的硬编码颜色、背景 URL 和 `wailsVersion` 常量需要后续按迁移表逐步替换。

## 被否决方案

1. **只使用 `prefers-color-scheme` 和 CSS media query**：无法表达平台资源、窗口 hooks、移动安全区和版本化用户主题。
2. **只读取 User-Agent/`navigator.platform`**：在 WebView、浏览器隐私模式和未来嵌入环境中不稳定，且不应成为安全或能力判断依据。
3. **由 Go/server 注入一份全局主题并让所有入口复用**：把 GUI 状态带入领域 composition root，破坏 CLI/MCP/HTTP 的边界，也无法自然覆盖浏览器/SSR。
4. **允许用户保存任意 CSS、HTML、JavaScript 或远程 URL**：增加 XSS、路径穿越、供应链和离线失败风险，无法可靠校验或迁移。
5. **把所有内容塞进一个 `localStorage` JSON**：损坏隔离、并发写入、版本迁移和清理都不可控；多键指针契约更容易原子切换和回收。
6. **无限等待环境探测或让探测失败阻止窗口**：平台信息不是业务前置条件，阻塞会使离线、浏览器和 runtime 变更时 GUI 不可用。
7. **不锁定 runtime、兼容所有 beta API**：会把生成 bindings 与启动时序变成不可复现的隐式行为；升级应是显式决策。
