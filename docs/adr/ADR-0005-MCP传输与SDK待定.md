# ADR-0005：MCP 传输与 SDK 选择

- 状态：`accepted / SDK pending`
- 日期：2026-09-19

## 背景

MCP 是独立的 AI Agent 适配层，不应因每新增一个内部功能就新增一个工具。当前 Wails 版本自带 MCP 示例，但产品能力 MCP 与 UI 控制型 MCP 的目标不同；具体 SDK 也可能随协议版本变化。

## 决策

- 产品入口固定为 `wailf mcp`，首期使用 stdio，适合本机客户端和最小网络暴露面。
- 工具按任务级和查询级聚合，控制在 15 至 25 个，并为危险操作提供确认和风险元数据。
- MCP 适配层隔离具体 SDK；本轮不锁定 `mcp-go` 或官方 SDK，不新增依赖。
- 后续 SDK 选择必须评估 stdio、结构化输出、取消、工具注解、维护状态和未来 Streamable HTTP 兼容性。
- Wails UI 控制型 MCP 只能用于开发/测试，不作为产品领域工具面。

## 后果

当前文档可以先稳定工具边界和安全策略，SDK 决策延后不会污染领域包。实现 MCP 前必须先创建替代 ADR，并补充依赖和版本说明。

## 被否决方案

- 首期同时发布 stdio 和 HTTP：鉴权与测试面过大。
- 每个内部函数一个工具：工具选择准确率和安全审查都会变差。
- 让领域模型直接依赖 MCP SDK：阻碍 GUI/CLI/HTTP 复用。
