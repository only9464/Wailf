# 安全与治理

> 文档状态：`accepted`  
> 适用范围：所有扫描、验证、连接、命令和 Artifact 工作流

## 1. 授权优先

Wailf 的默认前提是用户对目标拥有明确授权。平台不把“用户能输入目标”视为授权证明，而要求每次有影响的操作关联 TargetScope。TargetScope 至少包含：

- 目标表达式或资产集合引用；
- 授权说明或工单引用；
- 生效和过期时间；
- 允许的风险等级和操作类别；
- 创建者、最近修改者和审计关联。

过期、撤销或不匹配的 Scope 必须阻止新的主动 Job 和 Session 操作。应用级策略是全局上限，Scope 只能收紧。Scope 不分区资产；撤销后历史任务、观测、产物和审计仍可查询，运行任务和会话按策略停止或降权，并保留原因与结果。

## 2. 风险分级

| 等级 | 示例 | 默认策略 |
| --- | --- | --- |
| L0 | 本地格式转换、结果查询、布局管理 | 可直接执行 |
| L1 | 资产导入、被动分析、已保存 Artifact 查询 | 遵循应用级策略与导入审计 |
| L2 | 端口/服务探测、主动指纹、外部工具执行 | 需要有效 Scope 和用户确认 |
| L3 | 漏洞验证、认证测试、会话命令或文件操作 | 需要额外确认、审计和策略允许 |
| L4 | 可能改变远端状态或涉及持久化/利用的动作 | 首期默认关闭，未来需要审批策略 |

风险等级是策略输入，不是某个工具名称的永久属性；Connector 必须声明其实际影响。

## 3. 确认与审计

高风险操作的确认不能只存在于 UI 按钮状态中。入口需要把确认意图转换为领域请求，领域服务再次校验：

```text
请求 -> Scope 校验 -> 风险策略 -> 明确确认 -> 创建 Job/Session -> 审计
```

AuditEntry 至少记录：

- 时间、可选 Scope、actor 和入口；
- 动作、领域、资源 ID 和风险等级；
- 允许/拒绝/失败/取消结果；
- Job/Session/Artifact/request 关联 ID；
- 脱敏后的输入摘要、策略版本和错误 code。

审计记录不能包含明文密码、token、cookie、私钥或完整会话输出。删除 Artifact、撤销 Scope 和修改策略同样要审计。

## 4. 秘密管理

- 凭据只通过系统密钥库或等价的受保护存储读写。
- SQLite 只保存 `CredentialRef`，不保存秘密本身。
- localStorage、CLI 参数、stdout、普通日志、Artifact 索引和错误 detail 禁止出现秘密。
- CLI 支持从受控 stdin 或环境引用读取秘密时，必须避免回显并在进程结束后清理。
- 凭据轮换、失效和删除都需要可追踪的引用状态和审计记录。

## 5. 外部工具与连接器

Connector 是不可信输入边界：

- 固定允许的可执行文件、版本和参数映射；不接受任意 shell 字符串拼接。
- 为每个 Job 设置超时、并发、输出大小和临时目录限制。
- 取消时清理子进程、临时文件、socket 和文件句柄。
- 解析外部结果时限制深度、字段大小和字符编码，避免日志注入和资源耗尽。
- 连接器健康信息和原始错误只能进入受控诊断字段。

首期不设计自研 C2 Agent、载荷或 WebShell 植入流程；外部会话只通过生命周期和可选通道连接器接入。

## 6. 数据保留

| 数据 | 默认策略 |
| --- | --- |
| Asset/Job/Session 元数据 | 按应用级策略保留 |
| AuditEntry | 默认长期保留，可按合规要求配置 |
| Artifact 元数据 | 内容过期后保留索引和哈希 |
| 原始扫描输出/日志 | 按 Job/Artifact TTL，默认有限期 |
| Session 原始终端输出 | 默认不长期保存，按会话策略显式开启 |
| GUI 布局 | localStorage，支持导出/导入和清理 |

清理任务先写审计，再删除内容；失败时保留可重试状态。

## 7. 本地与远程边界

本地单用户模式不等同于无风险：恶意输入文件、外部工具输出和导入的 JSON 都必须进行大小、编码和结构校验。未来 HTTP/server 模式不得直接暴露本地模式的默认信任，需要独立身份、应用级访问策略、TLS、Origin/CSRF 防护、限流和审计 actor。

## 8. 事件响应

发现凭据泄露、越权执行、Artifact 篡改或连接器异常时，处理顺序为：

1. 停止相关 Job/Session 并撤销凭据引用；
2. 保留脱敏审计和诊断信息；
3. 隔离受影响 Artifact 和 Connector；
4. 更新 Scope、策略或连接器版本；
5. 在 ADR 或安全记录中写明影响、修复和迁移。
